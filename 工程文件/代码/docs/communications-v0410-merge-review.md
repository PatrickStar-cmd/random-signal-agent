# v0.4.10 接收汇合的数据定义与集成验收

## 🔱 实际汇合点

两条接收分支共享信源、发送处理、信道及全局参数。共享信道采样按观察值回放，每条接收器继续执行自身算法。汇合后再次运行下游解调与译码，生成信宿和误码统计。

| 汇合格式 | 输入数组 | 下游处理 |
| --- | --- | --- |
| 复符号 | 解调器实际收到的符号：已移除公共前导，并完成该分支的增益补偿 | 按共同星座重新解调，再执行译码 |
| LLR | 每个分支实际软解调得到的 `log(P(0)/P(1))` | 软译码与业务恢复 |

选择模式复制指定分支的数组；加权模式计算 `w₀x₀+w₁x₁`。两路输入需要相同形状、数值类型和采样率。复符号模式比较解调器及之后的配置；LLR 模式核对星座与软译码配置，允许各分支独立设置前置软解调方差。

`experience.observations` 中的独立 `merge-output` 观察点保存实际汇合数组。各接收积木的观察图继续显示该算法自身输出。`merge.input_reference` 标明汇合数据位于去前导和增益补偿之后，或采用正值支持比特 0 的 LLR 定义。

## 🫧 有效噪声方差

- 选择一路，以及权重 `[1,0]` / `[0,1]`，保留该路实际形成 LLR 的噪声方差。MIMO 接收的逐符号有效方差数组保持顺序与长度，兼容现有软检测预设。
- 一般加权的自动方差模式，以及输入携带有效方差数组的接收链路，采用实际汇合符号与最近星座点的均方残差估计噪声，记录为 `merged_decision_residual`。
- 用户显式配置的固定标量方差继续用于软解调。合并结果中的 `merge.noise` 保存使用的方差及估计方法。
- LLR 汇合直接使用两路已经计算的可靠度。码字误码数和符号判决从合并后的 LLR 计算，业务 BER 从实际下游译码输出计算。

## ✅ 核心验收

`scripts/test_communications_v0410_review.py` 的 8 项独立集成测试覆盖：

1. 实际融合 LLR 的硬判决与码字误码统计一致。
2. 独立汇合观察点及各接收积木观察图与运行数组一致。
3. AGC 与独立噪声估计两条接收路径：选择、单路权重及一般加权与后续 QAM16 解调一致。
4. 原有「复基带符号」端口可参与符号汇合。
5. 选择软接收路径保留该路估计方差及完整 LLR。
6. 独立软解调方差的两路 LLR 可以按权重汇合。
7. MIMO 逐符号方差在默认及自动方差设置下均保持所选路径的完整软输出。
8. OFDM 通感的负速度测量、通信恢复，以及公共训练与本机雷达参考的数据分工。
