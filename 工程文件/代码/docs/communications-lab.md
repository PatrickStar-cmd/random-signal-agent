# 通信原理仿真实验室

用积木搭出一条通信链路，再观察信宿收到什么。左侧积木工坊提供模块，中间搭建紧凑拼接链路，右侧显示信宿观察和选中积木的完整参数；下方集中展示指标与分析图。空白工程只放置信宿，电视窗口显示雪花屏。

v0.4.2「积木编程视图更新」部署包包含六类积木、六种模拟调制、第四章线路编码与基带信道、自动符号同步和固定/自适应均衡，合计 29 个示例。详见 [模拟调制](analog-modulation.md)、[线路编码与基带信道](baseband-coding.md)、[同步与均衡](receiver-recovery.md)。升级后重启服务并刷新页面；启动方式和运行依赖保持不变，无需模型 API Key。

## 第一个实验

1. 在 `工程文件/代码` 安装 `requirements-repro.txt`，按 [执行指南](exec.md) 启动服务。
2. 打开 `http://127.0.0.1:8000/#communicationsPanel`，或点击导航栏的“通信实验室”。
3. 选择“数字通信”示例。它连接随机比特、Hamming 编码、QPSK 调制、衰减、白噪声、QPSK 解调、Hamming 译码和信宿。
4. 点击 **🔨 Build**。程序检查输入类型、参数、收发配对和中间数据量，显示逐级检查结果；此时仍是雪花屏。
5. 点击 **▶️ Run**。右侧显示译码后比特，紫线为原始信源，绿线为接收输出，红点标出错误位。拖动滑块可查看整段接收结果。
6. 点击链路中的噪声积木，在右侧参数面板将 Es/N0 从 12 dB 调低到 0 dB，再 Build、Run，观察误码率和星座散布的变化。

数字通信、模拟信源 + PCM、文字传输和七个直接模拟调制示例均可修改。模拟示例包含 AM、DSB-SC、SSB、VSB、FM、PM 和窄带 FM。固定种子和完整配置能够复现同一次实验，改变种子获得另一组信源与信道随机样本。

另有十个线路码示例，以及 4-PAM/RRC/带限 AWGN、ISI/迫零均衡两个示例。新增非线性时钟、早迟门、Gardner、固定 DFE、NLMS 线性、NLMS DFE 和 RLS DFE 七个示例，目前共 29 个。选择基带/均衡示例比较均衡前后 RMSE；切到“接收眼图”“时钟跟踪”“均衡收敛”观察相应结果，详见 [同步与均衡](receiver-recovery.md)。

## 自己搭建

从积木箱拖动模块到链路中，或点击积木上的“＋”。链路中的拖动手柄与上下箭头用于排序；× 移除模块。信宿始终固定在末端。桌面左右并排，窄屏上下排列，手机可用添加和排序按钮完成操作。

积木工坊按链路顺序分为六类：**🎲 信源、🔀 发转换器、📡 调制器、🌊 信道、🎛️ 解调器、🔄 收转换器**。发转换器包含 PCM、纠错编码、交织和线路编码；数字调制器把比特映射为复基带符号，模拟调制器把模拟样本变为复包络。新增基带/PAM 形成器把线路电平或分组比特形成实波形；接收侧先滤波抽样，再在线路译码后进行解交织、纠错译码及 PCM 还原。这里的“转换器”指编码与数据转换，不表示射频上变频或下变频。

基本顺序为：

```text
信源 → [发转换器] → 调制器 → 信道 → 解调器 → [收转换器] → 信宿
```

方括号表示按实验需要添加。数字信源可以直接进入数字调制器；模拟信源可以直接进入 AM/DSB-SC/SSB/VSB/FM/PM，或先经 PCM 转为比特后进入数字调制器。发送端叠加多个编码器时，接收端按相反顺序译码，且重复次数、交织列数、PCM 位数和量程必须配对。例如：

```text
文字 → Hamming编码 → 交织 → BPSK → 白噪声 → BPSK解调 → 解交织 → Hamming译码 → 信宿
```

基带线路实验采用：

```text
比特 → [纠错编码/交织] → 线路编码 → 基带波形形成 → 基带信道
    → 基带抽样判决 → 线路译码 → [解交织/纠错译码] → 信宿
```

PAM 形成器直接接比特；线路电平须接基带形成器。NRZ/RZ、差分、AMI、Manchester、Miller、CMI 和 HDB3/HDBn 的编码、初态配对、PAM 阶数及波形/接收参数见 [基带指南](baseband-coding.md)。

每条链路有一个调制器、对应的解调器，以及至少一个信道积木；可以选择理想信道。连续的模拟信源逐点相加，连续的数字信源按顺序拼接，二者不能直接混合。信源集中放在开头。

每次修改参数、添加或移动积木，旧构建与旧输出立即失效，重新 Build 后才能 Run。“撤销/重做”最多保留 30 个编辑状态；切换应用分区保留当前工程与运行结果。

## 选中积木与完整参数

点击链路中的积木或用 Tab / Enter 选择，紫色外框标出当前积木，右侧参数面板同步切换。积木内的白色槽显示关键参数摘要；具体值在面板修改。符号同步、均衡和高级参数按组展开，所有已有参数均保留。仅切换选中积木不改变工程或运行结果；修改参数会使旧 Build 失效。

Build 会检查所有积木，包括未选中和已折叠的字段。发现空值或范围错误时，自动选择对应积木、展开参数组并定位输入框。清空和替换示例/导入工程使用页面确认框，可按 Escape 取消，成功替换仍可撤销。“定位选中积木”将画布滚动到当前模块。

| 信源 | 自定义比特 | 1–8192 个 0/1，可测试已知序列。 |

信道按积木顺序执行。先加噪声再衰减，会把噪声和信号一起衰减；先衰减再加噪声，噪声不随前面的衰减减小。可以放多个信道积木比较顺序的影响。

## 如何理解结果

原 BPSK/QPSK/16-QAM 数字链路是每符号一个复样本的**复基带模型**。I 是实部、Q 是虚部，合在一起描述符号的幅值与相位。该分支采用理想定时。实基带分支采用 `fs=Rs×sps` 多点波形，支持成形、带限、ISI、采样时钟漂移、自动符号同步及固定/自适应线性与反馈均衡；使用已知帧粗起点和名义码元率。直接模拟链路使用采样复包络，所有时间轴使用模拟采样率；其 FFT 边界、角调制参考样本和指标定义见 [模拟指南](analog-modulation.md)。

“模拟采样率”和“样本数”确定模拟信源的时间轴；“符号率”确定信道 I/Q 的时间轴。两个时钟独立配置，模拟样本先缓存为有限帧再发送，符号率不改变随机误码概率，也不表示实时传输或连续吞吐量。

上面的符号率解释适用于原复符号分支。实基带分支中“符号率”是线路编码后的实际电平码元率，Manchester 等每位产生两个码元；波形采样率及截止频率共同影响带限失真。接收眼图位于接收滤波之后、手动抽样偏移及均衡之前。

### 噪声和补偿

星座码本按等概率符号的平均能量归一化为 Es=1；单次有限 16-QAM 帧的实测平均能量可能略有不同。白噪声按照标称发送能量计算：`N0 = 10^(−EsN0_dB/10)`，I、Q 分量均为独立、方差 `N0/2` 的高斯噪声。因此前置衰减会降低实际接收信噪比。

Es/N0 是每符号能量与噪声谱密度的比值，不直接等于每信息比特的 Eb/N0。对于码率 R、每符号 k 比特的理想平均模型，有 `Es/N0[dB] = Eb/N0[dB] + 10log10(R·k)`；短帧填充和终止位会改变有效码率。[MathWorks AWGN 说明](https://www.mathworks.com/help/comm/ug/awgn-channel.html)

已知增益/相位补偿使用本次信道配置的总复增益相除，不估计真实信道，也不能恢复丢失符号。补偿也会放大已经进入的噪声。星座图画的是**补偿设置生效后的判决输入**；I/Q 图画的是**补偿前的信道输出**，不能把二者当成同一观察点。

实基带“采样 SNR”按发送有效段（含实际前导）均方功率和实噪声样本方差定义；带限 AWGN 的参数在限带之前定义。它与上述 Es/N0 以及模拟复包络采样 SNR 分开。固定均衡使用配置的线性冲激响应；自适应均衡使用实际发送的公共前导及后续接收判决，不用干净消息。有限 ZF 仍有外围残余 ISI，并可能放大噪声。公式见 [基带指南](baseband-coding.md) 与 [同步均衡指南](receiver-recovery.md)。

### 指标

- **译码后 BER**：错误位数 / 信源位数；模拟信源以发送端 PCM 编码比特为参考。
- **解调后、译码前 BER**：解调位与编码位逐位比较，可观察纠错前后的差异。
- **符号错误数**：硬判决星座索引与发送索引不同的数量，包含最后一个调制填充符号。
- **有效码率**：原始信息位 / 编码后位，包含编码填充与卷积零尾，不计调制器最后的符号填充位。
- **判决前 EVM**：`100% × sqrt(Σ|判决输入−发送符号|² / Σ|发送符号|²)`，按全部符号计算。它描述星座偏差，不是 BER。
- **模拟 RMSE**：信宿还原样本与原始模拟合成信源的均方根误差。无传输误码时仍有 PCM 量化误差；超量程会产生饱和误差。
- **Hamming 非零综合征数**：译码器执行纠错的码字数。多位错误可能误纠正，此数不等于成功纠正的错误数。
- **基带电平 RMSE**：全数据段抽样判决输入相对发送线路/PAM 电平的误差；详情同时列出均衡前 RMSE、线路展开倍率、违例数及均衡系数。有效码率不包含线路展开，可结合展开倍率计算传输速率。

接收图每次显示最多 256 点，可用滑块浏览整段；信道图取前 256 个符号，星座散点取前 1000 个符号。指标和 CSV 使用完整帧，未用显示点数代替全部数据。

## 保存与复现

浏览器自动保存编辑草稿，刷新后可继续填写未完成的参数，需要重新 Build。撤销历史与运行结果不跨刷新保留。

新增模拟及实基带积木、分类细分保留旧积木类型、参数、工程 schema 1 与浏览器草稿键，旧工程 JSON 仍可导入并构建。十个旧示例的 token、逐级计划和完整固定种子结果已对照一致。

- **导出/导入工程 JSON**：保留积木顺序、参数、种子和时钟设置，也可以分享未完成的工程；导入后通过 Build 检查。
- **下载信宿 CSV**：导出全部样本/比特、信源参考及错误标记；模拟样本带时间列。
- **下载结果 JSON**：包括完整工程、逐级类型/数量、全部指标与信宿数组，以及有限长度的信道/星座展示数据。

通信实验室有独立的工程和结果，不改写信号工作区的数据。本轮尚未接入快照库、最近 50 次处理历史或 PDF 报告，使用上述 JSON/CSV 保存通信实验。

## 配置、接口与验证

服务启动时读取 `config/communications.json`。默认限制：32 块积木、合并数字信源 8192 位、模拟 1024 点、中间 65536 点/位、同时运行 2 个实验。所有字段说明见 [执行指南](exec.md)。

| HTTP | 输入 | 输出 |
| --- | --- | --- |
| `GET /api/communications/catalog` | 无 | 积木定义、参数类型/范围、默认值、29 个示例与上限。 |
| `POST /api/communications/validate` | `{"program": ...}` | 规范化草稿，允许未填完的参数；不代表链路可以运行。 |
| `POST /api/communications/build` | `{"program": ...}` | 严格检查的 `program`、`token`、逐级 `plan` 与摘要。 |
| `POST /api/communications/run` | `{"program": ..., "token": ...}` | 接收结果、指标和图表数组；必须与 Build 的配置匹配。 |

POST 使用 `Content-Type: application/json`。参数/链路/token 错误返回 400，并发已满返回 429。Build 的 token 是规范化工程的 SHA-256，用于配置一致性检查；服务不保存编译会话，也不执行用户代码。

外部自动化可用上述接口配置和运行，并使用浏览器定位 `#communicationsPanel`、`#cmBuild`、`#cmRun` 操控界面，再对可见分区截图。数值验收脚本为 `python scripts/test_communications.py`；日志覆盖到 `logs/communications/latest.log`。浏览器验收与截图位置见 [执行指南](exec.md)。
