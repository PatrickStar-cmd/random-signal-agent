# 实现原理

## 从对话到工具

`server.py` 接收浏览器 HTTP 请求。`dialogue_agent.py` 按会话标识保存信号和对话状态，把“采集”“预处理”“分析”等意图转为函数调用。未配置模型时依靠关键词、数值提取和规则；配置模型后可用模型选择工具并组织解释。工具调用记录显示执行步骤。SSE 是一条持续返回事件的 HTTP 响应，前端逐步显示内容。状态存于内存，重启即丢失。

## 采集与随机性

`signal_processing.py`、`acquisition.py` 生成波形和噪声。采样率表示每秒样本数，时长与采样率共同决定样本数量。随机种子决定伪随机数序列；相同配置、种子和环境可以得到相同仿真样本。仿真保留干净信号作为参考；上传和麦克风没有真实干净参考，不能据此报告真实 SNR 提升。

CSV 单列按给定采样率生成时间轴，双列从相邻时间差的中位数估计采样率。数据应等间隔、数值有限；该加载器不是针对任意不规则采样的重建算法。“实时流”通道可由仿真产生，不代表实际硬件已连接。

加载器要求采样率为有限正数，双列时间严格递增且近似等间隔（时间间隔相对容差 0.1%，允许小幅导出舍入误差）。重复、倒序及明显不规则的时间轴会被拒绝，避免在不适用的时间轴上直接计算 FFT。

## 预处理与方法比较

滑动平均以相邻窗口的均值替代当前值，削弱快速变化，也可能抹平信号细节；中值滤波取窗口中位数，对孤立尖峰更稳健。鲁棒异常检测以中位数及绝对偏差估计异常，再抑制尖峰；去均值移除直流偏置。具体组合和参数在 `preprocessing.py`。

Agent 模式在 `dialogue_agent.py` 中生成候选方法和参数，结合平滑程度、相关性及有无参考等条件评分并选择。自动评分是课程演示启发式，不等价于所有任务下最优的滤波器。风险及控制建议由统计阈值生成，没有直接操控实际设备。

## 时域与频域

FFT 和 Welch 都先去均值。没有可用交流谱能量（谱功率和不超过 `1e-12`）时，谱熵约定为 0，FFT 不列出虚假的谱峰；这表示没有可归一化的谱分布，不代表恒定信号具有宽带噪声。

时域统计要求非空、有限的一维信号。只有一个采样值时没有相邻样本可用于统计过零，因此过零率约定为 0，避免对空差分求均值产生 NaN。

均值描述中心，方差描述波动，RMS 是平方均值再开方；自相关比较信号与延迟版本的相似性。频域分析通过离散傅里叶变换分解不同频率成分，功率谱衡量各频率贡献；主频取主要谱峰，谱质心和带宽描述频率分布位置及离散程度，谱熵描述归一化谱的分散程度。有限时长、采样率和窗函数影响估计，峰值不必等于真实系统唯一频率。

有干净参考时，SNR 以参考信号功率与误差功率之比取十进制对数并乘 10，单位 dB。演示固定 8 Hz 信号和 seed=42，用于核对完整流程。

## 随机过程扩展

`advanced_analysis.py` 的 AR（自回归）模型把当前样本写成若干过去样本的加权和，通过最小二乘法寻找使误差平方和最小的系数，再递推预测。AIC/BIC 把拟合误差与模型复杂度一起衡量；稳定性半径来自模型特征根。预测是模型假设下的短期外推。

Welch 功率谱把信号分成可重叠的小段，分别加窗并计算谱，再取平均，降低单次谱估计的波动。残差是实际值与 AR 预测之差，对残差的相关性检查帮助判断仍有多少结构未被模型解释。

Welch 返回实信号的单边功率谱密度（采样值平方/Hz）：负频率能量合并到正频率，除直流和偶数长度的 Nyquist 点外乘 2。把谱密度乘频率间隔后求和可检查交流功率；单位幅值纯正弦应约为 0.5。归一化使用采样率乘窗函数平方和，避免错误地少计算约一半能量。参见 [SciPy Welch 单边谱定义](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.welch.html)。

## 麦克风与报告

浏览器提交采样数组或编码 PCM16，后端识别噪声特征、实施频域噪声抑制并写 WAV；存在 FFmpeg 时可尝试转换 MP3，失败则保留 WAV。实际效果依赖录音环境。`run_demo.py` 通过编排器依次执行采集、处理、分析、决策，写出数据和报告，不依赖外部模型。

## 日志

发布脚本使用 Git 提交快照生成 ZIP，而不是遍历工作目录，避免把个人环境或运行数据打包。SHA-256 将 ZIP 的每个字节映射成校验摘要；下载后计算出的摘要一致，表示文件与发布产物一致。`RELEASE.json` 将版本与源码提交对应起来。

ZIP 条目按文件名排序，时间使用提交的 UTC 时间，权限与存储方式固定，避免构建时间、系统和压缩库版本改变包字节。调用 Git archive 时临时禁用自动 CRLF 转换并指定 LF，不改变使用者的 Git 配置。同一提交在 Windows/Linux 生成的 ZIP 可直接比较 SHA-256，确保发布文件与两平台验收的包一致。

Windows PowerShell 5 将重定向的原生 stderr 包装为错误对象，启动脚本在执行 Python 时允许记录这些文本，执行完成后检查退出码；警告不会中断服务，实际失败仍返回非零。Compose 的项目名限制为兼容字符，模板显式指定名称，避免从中文目录推导空名称。

发布验收从 ZIP 解压后建立全新虚拟环境，检查依赖和算法，再通过真实启动脚本运行服务，以 HTTP 请求验证页面、分析、流式回复、上传及合成音频下载。Docker 的健康检查定期请求 `/api/health`，但只证明服务可响应，因此还要执行功能验收。检查日志在 `logs/release/`、`logs/deployment/`，具体命令和配置见 [exec.md](exec.md)。

静态展示通过 `scripts/build_showcase.py` 对同一个 seed=42 的观测序列分别执行六种预处理，以已知干净参考计算每种方法的 SNR。图表的叠加曲线共享全局最小值和最大值形成的纵轴，保留幅值差异；显示曲线可降采样，数值指标始终由完整样本计算。上传观测 CSV 后没有干净参考，不能恢复这里的真实 SNR。

GitHub Pages 直接提供生成好的 HTML、SVG 和数据文件，不执行 Python，也不接收对话或分析任务。`logs/showcase/latest.log` 记录依赖版本、生成位置、样本数量、主频与 SNR 提升；`logs/regression/latest.log` 保存边界与统一纵轴回归检查。

`logs/server/server.log` 保存启动脚本输出，`logs/verification/latest.log` 保存集成检查结果，均覆盖写入。直接运行看终端；systemd/Docker 日志查看命令及全部参数见 [exec.md](exec.md)。输出数据、录音、上传文件和日志属于运行产物，不纳入仓库。

## v0.2.0：任务、快照与评分

FastAPI 负责请求校验和路由，Uvicorn 提供 HTTP/SSE。SSE 是一个持续输出文本事件的连接；此版本输出实际工具开始/结束、心跳与最终结果，断开连接不会取消后台任务。`request_id` 和参数摘要写入 SQLite，同一次重试读取原任务；不同内容复用同一 ID 会被拒绝。每个会话持有一把锁，避免同时修改其数组。有限线程池和队列控制同时执行的任务数。失败操作还原内存中的前一状态；进程突然退出时，恢复上一次成功保存状态，未完成任务标为失败而不重跑。单进程约束是锁生效的前提。

快照将 Python 数据类的普通字段编码为 JSON，把 NumPy 数组单独写入 NPZ，并用 SHA-256 检查数据完整性。NPZ 加载禁用 pickle，先检查解压规模、数组类型、维数及长度。SQLite 中的快照引用完整采样文件；绘图只使用它的显示副本，不会改变原始数据。ZIP 导入恢复结果和参数，不依赖再次请求外部模型；仅接受当前 schema 与算法版本。音频附件 URL 属于原服务，跨服务导入时清除这些链接，采样本身保留。

显示降采样把时间轴分为桶，保留每条曲线的桶内最小值/最大值，并合并为共同的、有序索引；这样短暂尖峰不会像固定步长抽样那样容易被跳过。HTML 报告使用同样方法，CSV 则输出全部采样。点数预算不足以同时保留所有曲线的所有极值时需增加预算，当前浏览器使用 520 点，足以分配现有的有限曲线数。

AR(1) 模板以 `x[t]=a*x[t-1]+sqrt(1-a²)*e[t]` 递推生成干净随机过程，再叠加观测噪声。`e` 为高斯创新，固定 seed+1；观测噪声使用 seed，两者不会复用同一随机流。正弦和脉冲干扰模板复用原生成器。

有参考时，评分为 RMSE 改善、与干净信号的相关系数、相对粗糙度误差三项加权和。RMSE 是逐点误差平方均值的平方根；粗糙度衡量相邻差分。抑噪/波形/瞬态目标的权重依次为 (65,25,10)、(45,45,10)、(35,25,40)，误差项取负。各项按 [-1,1] 或 [0,1] 截断，防止单位量纲或极端值主导排序。

无参考时无法知道真实误差或真实 SNR，评分只观察粗糙度下降、残差与输出的相关性、RMS 幅值变化；对应三目标权重为 (40,30,30)、(15,25,60)、(0,20,80)，瞬态目标另加最多 40 分的峰值变化惩罚。各项公开显示。平滑也可能抹掉真实细节，残差不相关也不保证信号正确，因此这些是启发式诊断，分数不能跨不同输入直接比较，也不应承诺某方法总是最好。评分不包含按方法名称添加的奖励。

参数搜索使用全量样本计算，只在候选参数数量超过预算时均匀选取有限候选；报告记录实际搜索数量和总耗时。540 例基准使用正弦、多频、扫频、脉冲和 AR 信号，记录 SNR/RMSE/相关、残差相关、幅值变化、谱熵和耗时。Welch 与 SciPy 对照时统一对称 Hann 窗、分段去均值、重叠取整和直流置零规则。浮点误差容差为 rtol=1e-10、atol=1e-12。

任务与实验数据存放在 `data/`，启动日志在 `logs/server/`，工作台/基准验证日志在 `logs/workbench/latest.log` 和 `logs/benchmark/latest.log`。错误任务通过 `/api/tasks/{id}` 可查询结果；队列满属于可用原 ID 重试的资源错误，不代表输入已被执行。

## v0.2.1：管理、兼容和进度修复

名称是快照元数据，重命名只更新清单，搜索在浏览器过滤列表；名称直接从原记录读取，避免用显示中的中间点拆分而截断。删除只移除同会话的命名快照，保留自动保存与共享采样文件，防止其他快照因文件被删而失效。没有引用计数或垃圾回收，因此删除不承诺立即释放存储。

应用版本表示产品发布；算法版本表示样本和结果解释契约。维护更新保持 schema 1 / algorithm 0.2.0，新增 app_version=0.2.1，旧清单缺少 app_version 仍可读取。不同算法版本继续拒绝导入。

进度缓存保留最近 256 个事件，以递增序号追踪读取位置。原来以数组下标追踪，缓存被截断后下标不再增长，导致新事件无法显示。现在读取序号大于上次游标的事件；缓慢订阅者可能跳过已淘汰历史，但仍看到最新进度与持久化最终结果。先读取完成状态，再读取事件，确保完成之前的最后工具事件被发送。

参数指纹忽略 respond_async，因为它仅决定返回方式、不改变计算；兼容旧版含 true/false 的摘要。服务端最后写入内部 operation 字段，客户端无法把不同操作伪装成同一任务。当前数据模式不会提交生成参数，选择新模板才重新生成数据。日志位置和覆盖规则保持不变。
